# Backward-compatible ingest API, but our own live-feed protocol

## Context

Radio-Scout replaces rdio-scanner. rdio-scanner's license (API_ACCESS_POLICY.md, effective 2026-01-03) splits its API: the **HTTP REST ingest API is fully open (GPL)**, but the **WebSocket API is proprietary** and explicitly prohibits reverse-engineering, replicating, or redistributing it. Recorders (Trunk Recorder, SDRTrunk) already push calls to rdio-scanner's ingest endpoints.

## Decision

Radio-Scout implements an ingest surface that is **byte-compatible with rdio-scanner's open HTTP ingest API** — `POST /api/call-upload` and `POST /api/trunk-recorder-call-upload`, including the load-bearing response strings clients depend on (SDRTrunk requires HTTP 200 + `Call imported successfully.`, health-checks on `incomplete call data: no talkgroup`, and drops-without-retry on `duplicate call rejected`) and duplicate detection. Existing recorder setups migrate to Radio-Scout with only a URL change.

We design our **own** real-time live-feed protocol from scratch. We do **not** reverse-engineer or replicate rdio-scanner's proprietary WebSocket API. A richer *native* ingest API plus first-party Trunk Recorder / SDRTrunk plugins come in a later phase (see [ADR-0002](0002-audio-object-storage.md) for how audio is delivered).

## Consequences

- Real-world testing can start immediately against the maintainer's existing Trunk Recorder on the Pi — no new plugin to install.
- Our client and live-feed protocol are unconstrained by rdio-scanner's design, which is what lets us fix the iOS background-audio problem (see ADR-0002).
- We must faithfully reproduce the exact ingest response strings and field-parsing quirks (Unix-seconds timestamps, TR's `sources` array vs SDRTrunk's singular `source`, `talkgroupTag`/`talkgroupName` vs `talkerAlias`, etc.) for drop-in compatibility.

## Amendment (#96, 2026-08-02): the promises keep, the shape changes

This decision's two operative promises — **duplicate detection**, and the ordering that keeps the archive consistent with the object store (ADR-0002: "ingest writes the audio object **then** inserts the DB row") — were both carried by the shape of one long function. #96 makes ingest **resolve, then decide purely, then perform**, and answer with an **Admission** ([`CONTEXT.md`](../../CONTEXT.md)) rather than an HTTP response. Both promises survive, differently held:

- **Duplicate detection is now a decision over rows, not a `COUNT` over a window.** One query reads the Calls already stored on the resolved channel inside `±dedup_window_ms`; a pure function decides which — if any — the arriving Call duplicates, and names it. Same query count, same inclusive edges, same rdio-compatible `duplicate call rejected`. What changes is that the decision is a value: the window's near misses are property-tested at both edges, including the out-of-order backfill case a recorder produces when it catches up after a blip — the case a surviving mutant lived in. #46's keep-best needs the candidate rows anyway, to compare the copies.
- **The write-before-row ordering is now a property of the types.** The recorder's facts (`NewCall`) no longer carry the object key or the byte length; those are `blob::StoredAudio`, which only a completed write produces, and `repo::insert_call` takes one. A row naming an object nobody wrote is no longer expressible, where before it was prevented by a comment. The orphan invariant is unchanged: a failed insert after a successful write still leaves an object for #10's grace-period GC to reclaim, and an **Encrypted Call** still stores no object at all (`None`, spec US 9).
- **The wire contract is unchanged and now pinned as one artifact.** Every Admission's status and body — including the two rejections that answer `200 Call imported successfully.` so a recorder never retries — is snapshot-tested together, because a diff there is a diff every recorder in the field would see.

The reason ingest stopped returning a response is #72: **Dirwatch** ingests Calls with no HTTP request to answer, and would otherwise have had to re-implement this pipeline. It also moves ADR-0011 rule 3's guarantee: an Admission is written down where it is *decided*, so a Call refused with nobody waiting for an answer still leaves its line.

## Amendment (#46, 2026-08-09): keep-best dedup — the same transmission, the better copy

rdio-scanner's duplicate key is `(System, Talkgroup, ±window)`, and it is the reason a patched call plays **three times**: a console patches three Talkgroups together, the recorder uploads the same audio once per member, and each upload names a different Talkgroup, so nothing in that key can see they are one transmission. Multi-site systems produce the same shape for a different reason. This amendment widens the test and adds a second decision beside it — which copy to keep.

**The duplicate test is now: same System, inside `±dedup_window_ms`, and reaching a Talkgroup in common** — its own canonical channel or an overlapping **Patch** membership, both compared as canonical Refs (#45 already resolved member Refs to their owner, so a merge and a patch are answered by one predicate). Three consequences worth naming:

- **The candidate read widened from one channel to the System.** It had to: the second copy may arrive on a Talkgroup that is genuinely different, or — rdio's issue #466 — on a patch-minted Ref no Talkgroup owns yet, which no query keyed on the arriving Call's channel can reach. Matching is [`ingest::admit`]'s, purely, over the rows. The System scope therefore lives in the *query* rather than in the decision, which is why `tests/ingest.rs` proves it over real rows, on both dialects, instead of a pure test proving it against itself.
- **The read stays flat.** Patch membership and per-frequency error counts for the candidates are fetched in one statement each and only when the window turned something up — so a Pi whose window is empty every time pays exactly the one statement it paid before, and `tests/ingest.rs` holds the cost equal across two window sizes rather than pinning a number.
- **A Ref the recorder named as this Call's own `talkgroup` is a patch member even before a row exists for it.** The #81 discriminator ("keep a patch ref only if the System has a Talkgroup for it") exists to tell Talkgroup Refs from the radio IDs SDRTrunk appends; for this one number there is independent evidence, and it is the Ref auto-populate is about to create. Resolving the array before the insert (which this ticket had to do, so the decision can see it) would otherwise drop a channel's own Ref from the first Call on it and keep it on every Call after.

**The better copy wins: audio first, then fewer decode errors, then longer Duration.** Errors outrank length because the extra seconds of a badly-decoded copy are usually squelch tail. A criterion **abstains unless both copies can answer it** — decode errors only exist where a recorder sent per-frequency signal detail — so a copy never wins by having said less, and a tie keeps what is stored, which means identical copies cost no write. rdio has no equivalent: first upload wins, permanently.

**Audio outranks all of it, in both directions**, and that ordering is not cosmetic. An **Encrypted Call** stores no audio at all (spec US 9) while still carrying Trunk Recorder's own duration and no `freqList` to fault — so it can *win* the comparison outright. Letting it would take playable audio away from a Listener in one direction and, in the other, discard the audio a second recorder really did capture, leaving a call heard **zero** times against US 10's "exactly once". So a copy with audio always replaces one without, a copy without never replaces one with, and only when the two agree does quality get asked.

**A later-arriving winner replaces the stored Call under its own id**, the enhancement pipeline's swap precedent (ADR-0002's immutable objects: a new key, the old object left for #10's orphan-GC, never a delete). The audio, the signal detail and everything the recorder said about the transmission become the winner's; the id, the System, the Talkgroup, the instant and the created-at stay. Patch membership is **unioned** rather than replaced, because it records what the transmission *reached* and the surviving row stands for every copy of it. Nothing is published to the live feed, because the Listener already has this Call and a second frame is the double-play this ticket exists to end. Enhancement is reset to `none` and re-offered, since the levelled output describes a copy that no longer exists.

**Replacement is bounded in storage time, and that bound is a promise `serve` keeps.** Two copies of one transmission carry the same `call_at_ms` however far apart they arrive, so a rule written only over that would make every Call in the Archive replaceable forever — and `Cache-Control: immutable` could then never be honestly sent. So a stored Call is open to a better copy for a bounded time measured from when it was *stored*, `serve` withholds `immutable` for exactly that long, and the arithmetic is written once (`ingest::still_replaceable`) and read by both. What it gives up degrades in the right direction: a better copy arriving after the bound is still recognised as a duplicate, so nothing plays twice — only the upgrade is missed.

That bound is **its own setting, `[ingest] dedup_replace_secs` (30s), and not `dedup_window_ms`** — because the two measure different quantities and only one of them is about the air. `dedup_window_ms` is transmission proximity over `call_at_ms`, which every copy of a transmission reports identically, so half a second is ample and widening it starts merging genuinely distinct back-to-back Calls. The replacement bound is *upload* separation over the wall clock, and Trunk Recorder posting one file per patched member takes seconds to get through them. Sharing one number would have meant either keep-best almost never firing on shipped defaults, or the matching window widened until it ate real traffic — the second being the worse failure, since it is silent.

**Both halves are configurable, and both default to the improvement.** `[ingest] dedup_scope` (`patched` / `talkgroup`) and `[ingest] dedup_keep` (`best` / `first`) return rdio's exact semantics in one line each — because a patch array is the radio network's claim, and a claim can be wrong in a way that silently costs a Listener real traffic.

The **Admission** gains a `Replaced` arm. It answers the recorder `200 Call imported successfully.` — the copy's audio *was* imported, and where it landed is not something a recorder has a branch for — and leaves its own INFO line, which is the only record the upload happened at all. A refused copy still logs `reason=duplicate` naming the Call that beat it, unchanged.
