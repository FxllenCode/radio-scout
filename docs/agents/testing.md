# Testing

How the suites are built and how to extend them. CLAUDE.md's *Testing & coverage policy* is the rules; this is the machinery behind them. A module's own testing notes (a seam it exposes, a cost it pins) are in its `//!` header.

## The harness: `common::TestApp`

**The harness is `common::TestApp` (#21), and since #90 it starts the *same Instance the binary boots*** — `instance::start`, not a hand-rolled twelve steps beside `main.rs`'s thirteen. A spawned app therefore runs the Retention sweeper and the operator log sink, and provisions its two credentials for real into an env file of its own. `TestApp::spawn()` / `TestApp::with_key("k")` brings up the real router on an ephemeral loopback port over a temp SQLite DB + temp filesystem store **whose temp dir it owns** (no `_tmp` binding to keep alive), and carries the drive + assert helpers: `get`/`get_json`/`get_range`/`post_bytes`/`header_of`, `upload(CallUpload::new()…)` / `upload_tr(CallUpload::tr(meta))` for synthetic Calls in either recorder dialect, `count::<E>()`/`calls()`/`the_call()`/`seed_call(new, audio_at("k.wav"))`/`seed_system` for rows, `stored`/`object_keys`/`put_object` for stored audio, `connect_ws()` + `subscribe`/`next_json`/`no_frame_within` for live-feed pushes, `login()`/`login_as()`/`post_admin_bytes`/`admin_request` for the admin surface (#19) over a **cookie-jar client** so a session behaves as it does in a browser, `add_downstream(url, scope)` / `queued_for(id)` / `deliveries_settled(n)` for the **Downstream** queue (#52) beside `Peer::start()`, a real stub peer that speaks `/api/call-upload` and checks the key it issued. Non-default wiring is `TestApp::builder()`, and since #90 almost all of it is a **configuration edit** rather than a subsystem assembled by hand: `.config(|c| …)` (the general seam) and `.toml("…")` (the file itself, resolved the way a boot resolves one), with `.ingest()`, `.enhancement()`, `.trusted_proxies()` (paired with `upload_via_proxy`) and `.database_url()` kept as one-line sugar over the same `Config`. Only two knobs are not configuration — `.store()` (S3, or a substitute that can be made to fail) and `.clock()` (#90) — plus the statement seam every spawned app carries whether or not it uses it (`refuse_statements_on` / `refuse_updates_to`, #97). `.admin(AdminAuth)` is gone: it handed the app a finished subsystem, which is exactly how the old harness could be green about an Instance that had never been provisioned; a shut admin surface is now the *outcome* `.without_credentials()` arranges. `TestApp::restart()` / `.restart_with(|c| …)` / `.restart_onto(store, |c| …)` is a real stop-then-start on one handle — the port is released, the archive and the env file survive — and replaced eight copies of the shared-database preamble in `tests/enhance.rs`. Its own tests are `tests/harness.rs` — read those first; they are the harness by example, and `tests/instance.rs` is the assembly's. **Build the plumbing into the harness, not into a test file:** a file-local shorthand that names the file's own domain (`recorder_app()`, a `form(…) -> CallUpload`) is fine and expected; a second hand-rolled `spawn`/multipart-builder/`reqwest::Client::new()` is the thing #21 deleted thirteen copies of.

## Waiting: `settle()`

**`settle()` is how the suite waits (#93), and nothing else is.** `app.settle().await` returns when every **Worker** — sweeper, enhancement worker, Mining sweep, Downstream sender, Webhook sender, tone detector, quiet scanner, listener sampler, log sink — owes nothing; `app.workers()` reaches one by name when the wait is for a *count* rather than for quiet (`settled_at_least(n)`, the only way from outside to tell the retention scheduler from its first tick). It can be believed because **work is owed from where it is handed over, before the task that will do it is even polled**: `Enhancer::submit` admits inside the ingest a test already awaited, `Downstreams::owes` admits for the Downstream sender inside the transaction that queued the delivery, and the boot sweep and the enhancement resume are both admitted *before* their task is spawned — so there is no window in which an Instance reads idle because a worker has not woken up yet. That is what makes an assertion of **absence** honest, where a sleep can only ever say "not yet" and gets longer every time a loaded runner disagrees with it; it replaced four bespoke pollers and the ~700ms of fixed sleeps, two of which existed only to prove that nothing had happened. **Adding a sleep is the wrong answer here** — if `settle()` is not enough for some new asynchrony, the fix is that the new thing is a Worker.

## Fault seams

- **Making a specific I/O call fail is a seam at the module's own interface (#37, reshaped by #97).** A worker's error arms — the enhancement worker settling a Call `skipped`, ingest declining to queue one, serving telling "gone" from "broken" — are unreachable while the only store is a filesystem that works and the only database is one that answers. **The rule is: name the dependency at the interface and substitute there** — never damage the thing underneath, and never encode a caller's internal call order in the fault machinery (ADR-0009's #97 amendment says what that cost). Three interfaces, and their tests are `tests/harness.rs` and `src/enhance.rs`'s own `mod tests`:
  - **`blob::AudioStore`** is the port an `AppState` holds and `BlobStore` implements — put, size, get, get_range, delete, list, presign, in bytes and keys rather than `object_store`'s vocabulary. `common::faulty_store(dir)` → `(FaultyStore, Faults)` is a real store behind a substitute that does what it is told: `fail_puts()`, `fail_reads()` (broken → 500), `hide_reads()` (gone → 404) and — over a store of your own, via `common::faults_over_store` — `fail_presigning()` (#92, the only way to reach `stage=sign-audio-url`, since only an S3-shaped store ever signs). **`fail_reads`/`hide_reads` are the whole point**: no real store can fail a read after a successful stat — a filesystem object made unreadable fails its stat too, because `LocalFileSystem` opens the file to size it — so the previous answer had to park a real read inside the store while a real object was pruned, and had to know that serving stats before it reads. An interface can simply say it. Anything not switched is a passthrough; adding one is four lines.
  - **`db::Db` / `db::Txn`** is the handle every statement goes through, composed rather than constructed. `TestApp::refuse_statements_on(table)` refuses everything naming it; `TestApp::refuse_updates_to(table)` refuses only what changes a row, leaving the reads *and inserts* an update arm needs to be arranged through the app's own front door. Both raise `common::REFUSED` — **ours, on both dialects** — and a rule matches the **quoted table name**, which sea-orm writes identically on both (the statements around it are not identical: a prepared Postgres statement binds `$1` where SQLite binds `?`, which is why the rule matches an identifier rather than a whole statement). **Transactions are inside the seam**: `Db::begin` hands back a composed `Txn`, so ingest's frequency-roster insert is as refusable as a statement outside one. What this replaced was `DROP TABLE` plus a trigger written twice in two dialects' procedural SQL, recognised by matching each driver's own wording for "no such table". The same decorator also **counts** (#86) — `TestApp::statements_issued()` is a monotonic total, so two samples either side of some work say what it cost and two sizes say whether that cost grows per Call. **This is the only way an N+1 is visible from outside**, because the answer it returns is correct and only the round-trips behind it are wrong; it is what holds the live-feed Backfill to a constant. It counts the test's own queries too, for the same reason a refusal applies to them — one handle — so sample around the app's work and nothing else.
  - **`enhance::Archive`** is the six questions enhancement asks of the world — pending Calls, a Call's audio, read, write, settle done, settle skipped — and `enhance::step` returns a `Settled` (`Enhanced` / `Vanished` / `Skipped { reason, cause }`) rather than only a WARN — *settled*, not *outcome*, because CONTEXT.md reserves that word for **Admission**. `Enhancer::resume` returns a `Resumed { queued, shed }`, so "the last process left eight Calls and a one-deep queue" is a value rather than two applications sharing a database and a directory. Every failure arm is a `#[rstest]` case over a substitute; `tests/enhance.rs` keeps what integration is for — that the worker is wired into a running Instance.
  - **`LogCapture::storing(&db, config)` (#30)** sends the test thread's logging into the app's own database as well as the capture, exactly as `observability::subscriber` wires the two layers in production — so `tests/logs.rs` drives a real request and reads the result back through `GET /api/admin/logs`, which is the only place an operator sees it. `TestApp::store_logs()` is the one-liner; `await_logged(msg)` polls the endpoint (the sink is asynchronous by design, so there is nothing to await from outside), and `seed_log` writes a row directly for the tests about filtering, ordering and paging.
  - Some arms have **no seam at all**, and the honest answer is to say so rather than fake one: the window between ingest's insert transaction and its read-backs holds no I/O to park in and no statement a trigger can fire on, because SeaORM reads every inserted row back *inside* the insert, children included. `queue_for_enhancement`'s arms are therefore unit-tested in `src/ingest.rs`'s own `mod tests` over a real SQLite database, the way `src/retention.rs` and `src/startup.rs` already do.

## Recorder artifacts

**What runs on the recorder is tested by running it (#43, #44).** Both shipped recorder-side artifacts are driven for real against a `TestApp` over real HTTP rather than asserted about — `tests/uploadscript.rs` runs `radio-scout-upload.sh` with the three arguments Trunk Recorder really appends, and `tests/trplugin.rs` **compiles the plugin's own C++ upload core** and drives it. A committed `.multipart` fixture claiming to be what either emits stays green when they change underneath it, which is the whole failure mode. The plugin is split for exactly this: `radio_scout_upload.{h,cc}` includes no Trunk Recorder header and holds every decision (which audio file, which talkgroups, the POST), while `radio_scout_uploader.cc` is a shim that only reads fields off a `Call_Data_t` — and *that* file's only proof is the `trunk-recorder-plugin` CI job, because a hand-written `Call_Data_t` would prove the fake matches the fake. Both suites **skip loudly** where the machine lacks the tool (`curl`; a C++ compiler with libcurl headers) — but a machine that *can* build the plugin and then can't **fails**, never skips.

**Trunk Recorder has two shipped ways in, and a feature goes into both or neither.** `radio-scout-upload.sh` (#43) and `plugins/trunk-recorder/` (#44) are two programs in two languages posting the same contract; teaching one to send something new and forgetting the other is invisible from either side, and surfaces as an operator's Calls quietly carrying less than their neighbour's depending which path they happened to pick. This is not a convention to remember — **`tests/trplugin.rs::the_upload_script_and_the_plugin_land_the_identical_call` runs both against two instances over the same call files and compares the rows whole**, so anything either learns to send and the other does not fails the suite, including fields that do not exist yet. It is also how the first divergence was found: the script sent `audio/x-wav` where the plugin sent `audio/wav`. If a change genuinely belongs to only one of them — a `uploadScript`-only flag, say — the divergence has to be argued in that test, not worked around it.

## Dual-dialect

**Dual-dialect is done (#22).** Set **`TEST_POSTGRES_URL`** and every `TestApp::spawn` in every binary lands on Postgres, each on a `rs_test_<uuid>` database of its own — the isolation a SQLite-file-per-test gets for free, bought. Unset (the everyday loop, any machine without Docker) stays SQLite, so nothing about local TDD changes. CI runs the suite twice and feeds both runs into one coverage profile. What differs between the dialects, and why `break_table` / `missing_table_cause` exist rather than a pinned SQLite string: [`docs/agents/dual-dialect.md`](dual-dialect.md). `.database_url()` remains the per-call-site override.

## The browser layers

**End-to-end (Playwright) — wired up in #15.** `client/e2e/` + `client/playwright.config.ts`, run with `npm run test:e2e`. It is deliberately five specs, Chromium only, over a **production build served by `vite preview`** (the config builds first): jsdom has no service worker, no cache storage and no manifest processing, and the worker only exists in a build — so this is the only layer that can prove "installable + works offline". CI runs it as an advisory job (#22) until it has a track record there. Layering, per [Testing & coverage policy](../../CLAUDE.md#testing--coverage-policy):

- **Vitest Browser Mode** is the middle layer — real-browser component tests for the audio player + Media-Session *wiring* (#34): `client/vitest.browser.config.ts`, `src/**/*.browser.test.tsx`, `npm run test:browser`. Chromium via the Playwright binaries #15 already installs, and **deliberately separate from `npm run test`** so the jsdom loop stays seconds long and keeps owning the one measured coverage profile. Prefer it over Playwright component-testing. What it reaches is the **platform's verdict**, and the overlap with jsdom was *measured* rather than assumed. Every mutation tried — a wrong RIFF length, a lying WAV format tag, a bad PNG chunk CRC, a missing rewind, a `setPositionState` pair the spec forbids — fails in **both** layers, and a wrong zlib adler32 fails **only in jsdom** (Chromium's PNG decoder is lenient). Browser Mode is not a superset and does not catch a class of bug jsdom misses today. What it does is change *whose* judgement is being asserted: the jsdom tests check that our code produces what we intended, by parsing the bytes ourselves and holding a fake `MediaSession` to what it was handed — so they would all still pass if the *platform* moved under us. This layer is the one that would notice a Chromium release that stopped accepting our hand-rolled PNG, an autoplay rule that changed, or a decoder that tightened. It also removes the last mock from the `play()`-rejection path. Chromium's autoplay policy is left on, so a test wanting audio clicks first and one wanting the refusal does not — and that one needs its own file, because user activation belongs to the page. One trap worth knowing: Chromium stores Media-Session artwork URLs **without reading the bytes**, so asserting `metadata.artwork` is non-empty proves nothing at all (a corrupted-CRC PNG passed it); the test decodes each URL through `createImageBitmap`.
- **Narrow Playwright E2E** covers PWA install criteria, service-worker registration/scope, offline app-shell serving, and that the worker never answers `/api/*` from cache.
- **iOS background audio + lock-screen/Control-Center controls are a real-device manual gate** — Playwright's bundled WebKit is not iOS Safari and cannot validate them. There is no CI substitute. The executable checklist is **§14 of [`docs/research/ios-gap-bridging-mechanism.md`](../research/ios-gap-bridging-mechanism.md)**.
